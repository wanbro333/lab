# 成员分工与后续任务

更新日期：2026-11-14。基础工程、采购/收货后台及确认入库已完成，详见 [开发进度](11-development-status.md)；整体设计见 [总体指引](00-project-guide.md)。下表是待完成工作，不代表已指定具体成员。

| 工作包 | 建议负责人 | 依赖 | 验收条件 |
| --- | --- | --- | --- |
| 库存汇总与期初数据 | 后端 A + 前端 B | 现有批次模型、明确旧台账含义 | 按物品/库位查询，数量有来源，不重复计算旧数量；前端显示真实库存 |
| 领用/借用出库 | 后端 A | 批次余额、角色与领用规则 | 单据/明细、指定批次、余额不足拦截、并发扣库、流水来源及事务测试 |
| 归还入库 | 后端 A | 原出库单/明细 | 分次归还、原单原行一致、累计上限、防重复、事务测试 |
| 采购 API 与页面 | 后端 B + 前端 C | 现有采购模型/批准服务、接口权限约定 | 草稿编辑与批准联调；复用服务并验证状态限制 |
| 收货 API 与页面 | 后端 C + 前端 B | 现有收货模型/入库服务 | 分批收货、库位/批次录入、确认反馈；失败和重复操作有明确结果 |
| 完善审批 | 后端 B | 审批级数与角色规则 | 提交/驳回/取消、审批记录和合法状态转换；不能仅增加枚举 |
| 基础资料 API | 后端 B + 前端 B | 物品/供应商/库位模型 | 详情与维护、校验、启用状态和权限；不得破坏历史关联 |
| 用户与角色 | 后端负责人 | 讨论权限矩阵 | 逐接口授权、账号发放、自助资料与改密、项目角色区分 |
| 科研项目 | 后端成员 + 前端成员 | 项目字段和参与规则 | 项目与成员表，角色/加入时间，成员去重与访问权限 |
| 公告与首页数据 | 后端成员 + 前端 A | 发布权限与公告模型 | 公告发布/读取，首页展示真实内容与空状态 |
| 智能查询 | AI／后端成员 | 数据权限、稳定查询接口 | 会话/消息、后端接 Dify、来源可查、失败不阻塞手工操作 |
| 测试与文档 | 每个任务作者＋审查人 | 与各任务同步 | PR 有操作步骤、截图、失败场景、接口更新 |

人数较少时一人兼任多个工作包，但一个 PR 仍围绕一个小目标。

建议按以下顺序继续：

1. **统一库存来源**：先做库存汇总和旧台账衔接；成员同步启动环境、接口约定与角色设计。
2. **补全库存流转**：领用/借用 → 归还，扩展流水来源、数量方向和并发保护。
3. **前后端联调**：采购/收货等 API 与页面可按已确定接口并行开发，复用现有服务。
4. **完善协作能力**：审批历史、科研项目、公告、个人资料、智能问答。
5. **按需要增强**：附件、打印导出、中英切换、预警、设备逐台管理、盘点/调拨/报损和部署。

新成员无需重建已经存在的采购/收货模型，应先阅读模型、服务和测试。状态枚举不等于操作已完成，具体以进度表为准。

开发前至少在 Issue 中写清：谁操作、从哪个页面开始、输入什么、后台如何保存、失败怎么办、怎样算完成。前后端可以并行，但接口约定应先于各自实现。

公共文件协调：App.vue、router/index.js、config/settings.py、config/urls.py、锁文件和公共样式由负责人收口；各成员先新增自己的模块目录。共享数据库模型改动提前说明，避免同一 app 同时改同一个字段。
