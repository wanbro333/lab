# 成员分工与后续任务

先完成启动验收，再分配业务任务。下面是任务模板，不代表已指定具体成员。

| 工作包 | 建议负责人 | 依赖 | 验收条件 |
| --- | --- | --- | --- |
| 公共布局与首页 | 前端 A | 基础工程 | 窄屏可用、真实通知接口、无假数据 |
| 物品详情与编辑 | 前端 B + 后端 A | 物品字段约定 | 查详情、校验、权限、更新反馈和测试 |
| 设备／材料数据模型 | 后端 A | 确认逐台设备和批次规则 | 迁移可重放，旧示例数据可迁移 |
| 采购单 | 前端 C + 后端 B | 先定角色与审批状态 | 草稿、明细、提交、审批、状态限制 |
| 收货入库 | 后端 C + 前端 B | 采购和库存模型 | 分批实收、事务、重复确认防护、库存流水 |
| 智能查询 | AI／后端成员 | 数据权限、稳定查询接口 | 后端接 Dify、来源可查、失败不阻塞手工操作 |
| 用户与角色 | 后端负责人 | 讨论权限矩阵 | 后端逐接口授权、账号发放、资料与改密 |
| 测试与文档 | 每个任务作者＋审查人 | 与各任务同步 | PR 有操作步骤、截图、失败场景、接口更新 |

人数较少时一人兼任多个工作包，但一个 PR 仍围绕一个小目标。

建议按四个阶段推进：

1. **基础对齐**：每人独立启动，完成一次练习 PR，确认真实附件和需求清单。
2. **物品台账**：确认设备／材料／批次结构，做详情、编辑、分类与库位字典。
3. **一个业务闭环**：先选择领用归还或采购收货；为状态、并发、撤销补充测试。
4. **增强能力**：再加智能查询、打印导出、中英切换和部署。

开发前至少在 Issue 中写清：谁操作、从哪个页面开始、输入什么、后台如何保存、失败怎么办、怎样算完成。前后端可以并行，但接口约定应先于各自实现。

公共文件协调：App.vue、router/index.js、config/settings.py、config/urls.py、锁文件和公共样式由负责人收口；各成员先新增自己的模块目录。共享数据库模型改动提前说明，避免同一 app 同时改同一个字段。
